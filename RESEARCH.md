# Placard access research

Read-only reference was frs0n/placard 7f470dd0242f9d69ea5ad17e521566487706c891. Its source is GPLv3. No source was copied into this repository. Newly written code is an independent behavior-level implementation added to the existing MIT Gester-derived adapter; it is not presented as a license opinion.

Placard calls this method worse_query. Its normal path uses libsystem_containermanager container_query_create, container_query_set_class (7, own app-group), container_query_set_group_identifiers (a scalar XPC string), container_query_operation_set_part (3, cache), container_query_operation_set_flags (0x8000000000 on iOS27; alternative 0x800000000 for iOS26), container_query_get_single_result and container_copy_sandbox_token. It does not set part_domain. Its own app-group Library/Caches is temporarily a symlink to the requested path; sandbox_extension_consume consumes the returned extension before Caches is restored. It then accesses the canonical target, not a retained Caches alias. Separate root, metadata, datastore and descriptor grants avoid assuming a root grant is recursive.

It discovers exact UUID children of the Application/InternalDaemon/PluginKitPlugin data roots using fsgetpath on the app's data volume, with a bounded inode pass; xattr identity or MCMMetadataIdentifier identifies com.apple.PosterBoard. It does not need to list the parent directory. App groups are obtained from process entitlements with an own Mach-O embedded-entitlement fallback, then checked via FileManager group-container lookup.

## Device follow-up, native-picker v3

Owner's delivered v2 reports a parsed embedded entitlement dictionary but zero usable groups. This alone does not distinguish a missing group key, unavailable process query, a declared group rejected by the probe's name filter, or a nil OS group-container lookup. The old probe discarded every group not exactly equal to "group." plus the runtime bundle ID before logging its value. Placard instead prefers that spelling but also checks every declared group.* against the OS container lookup. A signer-modified bundle/group pairing could therefore be discarded only in the probe. This is a concrete source discrepancy, NOT a confirmed diagnosis of this device.

The probe now logs each acquisition symbol/task result, the runtime query value/type/CFError, embedded group key/value/type, bundle-derived preferred name, and each declared group's OS lookup result. It preserves the requirement that candidates come from the app's own signature/process declarations and return an OS group-container URL; it does not guess another app's group. containerURLForSecurityApplicationGroupIdentifier has no NSError out parameter. Its immediate errno snapshot is explicitly labelled non-authoritative, with a separate lstat result when a URL exists. None of these observations is phrased as proof the signer removed an entitlement.

The previous picker was SwiftUI fileImporter with [.item, .data, .zip], followed by a case-insensitive tendies-extension check and uncoordinated copy. The exact device failure stage remains unknown. The replacement is UIKit UIDocumentPickerViewController(forOpeningContentTypes: [.item], asCopy: true). It logs presentation, native delegate selection/cancel, returned extension, security-scope result, coordinated content type/size and archive validation. Import failures appear in an alert as well as the log. Security scope is held through coordinated read and private copy; an already-sandboxed import copy does not require startAccessing to return true.

## Device follow-up, live-discovery v4

688a606 successfully imported the archive and found the signer's renamed own group. Owner confirms the ENTIRE log ends at usable groups=1. The very next operation is copyCandidateJSON: synchronous inode enumeration previously allowed 45 seconds and returned all logs only on completion. This is a concrete blind spot, not proof of which syscall stalled or whether the process crashed.

Add immediate live worker checkpoints before/after discovery, scratch-volume setup, identity xattrs, access acquisition, container-manager result/token/consume calls and Caches manipulation/restoration. Native callbacks dispatch asynchronously to the UI, never synchronously wait on it. Inode enumeration now checks a 6-second cooperative budget between syscalls and reports progress every second. Candidate verification allows at most 8 attempts and a 20-second cooperative discovery budget. Automatic legacy root sweeps are skipped instead of starting hundreds of additional access calls. A 12-second UI watchdog explains that the current call is still outstanding without clearing busy or starting competing work.

These are cooperative bounds, NOT hard timeouts on fsgetpath, xattr, filesystem or synchronous container-manager IPC. Killing/cancelling a background worker while its Caches alias exists would be unsafe. Native normal/exception exits after the canonical strategy's original Caches move now use a finally restoration path, including failed alias installation/validation; concurrent conflicting paths remain untouched with the original backup retained. Process death or an IPC that never returns cannot run finally. No device access or install success has been demonstrated.
